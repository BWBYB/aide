# ADR 0005：token 估算用 CJK 感知的本地近似

- 状态：已接受 ｜ 日期：2026-10-31 ｜ 关联：M1 / C 组压缩

## 背景

压缩阈值要判「上下文占了窗口的 80%」，必须先算「现在占多少 token」。
M1 不引入真实 tokenizer（不让纯函数依赖模型），故用本地近似。
第一版是 `len(text) // 3`，按英文校准。

## 问题

语料以中文为主：

| 内容 | 实际 token | `len//3` 估出 | 偏差 |
|---|---|---|---|
| 中文正文 | 约 1 字 / token | 1 字 → 0.33 | 低估 3 倍 |
| Python 代码 | 约 3–4 字符 / token | 接近 | 可接受 |

后果不是「测试不稳」，而是**生产阈值的量级错误**：
窗口 128K、阈值 80% = 102K token 触发；用 `len//3` 要等到 307K 字符才算出 102K，
中间那 200K 字符早把请求撑爆。现象是「压缩好像没生效」，实际是尺子坏了。
更隐蔽的是：断言只依赖同一口径下的相对关系，所以**测试全绿、线上永不触发**。

## 决策

CJK 按 1 字 1 token，其余按 4 字符 1 token：

```python
def count_tokens(text: str) -> int:
    cjk = sum(1 for ch in text if "\u4e00" <= ch <= "\u9fff")
    return cjk + (len(text) - cjk) // 4
```

误差从 3 倍压到约 30% 以内。

## 约束

1. **单点可替换**：`compress(count=...)` 接受注入，M5 换真实 tokenizer 只改这一个函数。
2. **断言只依赖相对关系**：不硬编码绝对 token 数，换实现不会让测试「迁就实现」。
3. **必须有测试挡住回退**：`test_count_tokens_weights_cjk_per_char` 断言
   「250 个汉字 = 250 token」且 `count_tokens > len//3 * 2`，一旦有人改回英文系数即红。

## 后果

- 正面：压缩阈值在中文语料上不再低估三倍；替换点单一，M5 迁移成本低。
- 负面：仍是近似，中英混排与代码场景偏差约 30%，因此**不得用估算值做计费或对外报数**。
- 解除条件：M5 接入真实 tokenizer 后本 ADR 作废，阈值语义不变。
