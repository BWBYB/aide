# ADR 0003：上下文布局固定为「静态前缀 + 轨迹 + 尾部状态栏」

- 状态：已接受
- 日期：2026-10-30
- 关联里程碑：M1

## 背景

书稿第 2 章的核心结论是：**上下文前缀越稳定，KV Cache 命中率越高**，而缓存命中直接决定延迟与成本。
一个每轮都变的系统提示词，等于每轮让缓存整体失效。

同时，Agent 每轮又确实需要看到"现在几点、调了几次工具、TODO 到哪了、上一步为什么失败"这类易变信息。

## 决策

上下文严格分三段，顺序固定：

1. **静态前缀**：系统提示词 + 工具定义 + 长期不变的规则。**逐字节稳定**，一旦确定不再改写。
2. **轨迹**：用户消息、模型回复、工具调用与结果，只追加。
3. **尾部状态栏**：时间戳、工具调用计数、TODO 快照、最近错误摘要。作为**最后一条 user 消息**追加，每轮替换。

## 被否决的方案

1. **状态栏写进系统提示词**：直觉上最"干净"，但每轮都让前缀变化，缓存命中率归零，成本最高。
2. **每轮重排消息顺序**（把最相关的放前面）：破坏前缀与轨迹的稳定边界，且与"只追加"冲突，难以回放。
3. **把状态栏做成 assistant 消息**：部分厂商对连续同角色消息有额外约束，且回放时容易与真实模型输出混淆。

## 后果

- 正面：前缀哈希可写成断言（`test_prefix_hash_stable_across_turns`），缓存收益可被评估集量化。
- 负面：状态栏占用的尾部位置会让"最近一轮"的注意力权重偏高，需要在 M5 里检查是否导致短视。
- 校验方式：M1 的单测对前 3 轮静态前缀做 sha256 相等断言；`make replay` 逐轮打印 `prefix_sha256`，变化点必须有日志说明（压缩触发）。
